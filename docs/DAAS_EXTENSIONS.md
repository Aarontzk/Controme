# DaaS Runtime Extensions

These runtime hooks live in Buildpad DaaS, not in the Next.js repository. Keep
this file and the code snapshots in `docs/daas/` in sync with the live DaaS
configuration so the setup can be recreated for another environment.

## Installed Extensions

| Name | Event | Type | Purpose |
|---|---|---|---|
| `qc-reference-autoversion` | `products.items.update` | action | FR-03: append a row to `product_reference_versions` when reference Lab/tolerance/threshold fields change. |
| `qc-reject-notify` | `qc_lots.items.create` | action | FR-04: append a `qc_notifications` alert/warning when a reject or warning-band lot is created. |

Both extensions use DaaS item services with `{ elevated: true }`. The extension
logic is the authority for these derived rows, while DaaS still records the
originating user in audit fields/activity logs.

## Supporting Collection

`qc_notifications` is a DaaS collection used by `qc-reject-notify`.

Expected fields:

| Field | Type | Notes |
|---|---|---|
| `id` | uuid PK | Auto-generated by DaaS. |
| `lot_id` | m2o -> `qc_lots` | Lot that triggered the notification. |
| `product_id` | m2o -> `products` | Product for dashboard filtering. |
| `level` | string/enum | `alert` for reject, `warning` for warning-band pass. |
| `status` | string/enum | Copied from `qc_lots.status`. |
| `delta_e` | float | Copied from `qc_lots.delta_e`. |
| `message` | string | Human-readable dashboard message. |
| `read` | boolean | Defaults to `false`. |
| `date_created` | datetime | DaaS special field. |

Read permission is granted to the existing QC viewer policies so dashboards can
consume the collection. Direct client creation is not required; rows should be
created by the DaaS extension.

## Recreate

Use the DaaS MCP `extensions` tool:

1. Create `qc-reference-autoversion` from
   `docs/daas/qc-reference-autoversion.js` with event
   `products.items.update`, type `action`, status `active`, timeout `5000`.
2. Create `qc-reject-notify` from `docs/daas/qc-reject-notify.js` with event
   `qc_lots.items.create`, type `action`, status `active`, timeout `5000`.
3. Ensure `qc_notifications` exists with the supporting fields above.
4. Grant read permission for `qc_notifications` to operator, PPIC, and manager
   viewer policies.
5. Trigger one product reference update and one reject/warning lot create, then
   check extension logs and collection rows.
